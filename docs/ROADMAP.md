# Role and mission

You're the lead engineer on My AfriAnalyze, an equity research platform for listed companies in Africa, starting with the Dar es Salaam Stock Exchange (DSE), then the Nairobi Securities Exchange (NSE) and the Uganda Securities Exchange (USE).

The product does what a CFA Institute Research Challenge team does, for any listed company:
- reads the annual reports and the non-financial information,
- analyzes every major line of the financial statements,
- estimates beta and the cost of equity in local currency,
- values the company with the right model for its sector,
- runs bear, base and bull scenarios,
- produces a fair value range, a 12-month target price and a model view (undervalued, fairly valued, overvalued, shown as BUY / HOLD / SELL when enabled),
- lists the risks, each one backed by a source.

Stack already in the repo: Next.js (App Router), FastAPI, PostgreSQL, Celery, Redis, Docker Compose, Terraform for GCP. Keep this stack unless something is broken beyond repair. If you want to change it, ask first.

Goal of this project: take the repo from a demo with hardcoded data to a product people pay for.

# Rules for the whole project (follow these every milestone)

1. **No invented numbers.** Every figure in the UI comes from the database and links to its source (URL or document, page, retrieval time). Missing data shows "Not available" plus the reason. No placeholders, sample data or fallback constants anywhere outside test fixtures, and test fixtures never ship to production builds.
2. **Deterministic finance.** Python code computes every figure, ratio, valuation and recommendation. The LLM may only explain, summarize and answer questions using stored numbers, with citations. It never produces a number that isn't already in the database.
3. **Proof before "done".** A milestone is done only when its acceptance checks pass. Paste command output, test results and screenshot paths into `docs/PROGRESS.md`. Never call the system "complete".
4. **Honest gaps.** Keep `docs/KNOWN_GAPS.md` current. Anything still fake, partial or untested goes there.
5. **Stop at each milestone.** When a milestone's checks pass, commit, write a short report (what works with proof, what doesn't, decisions you need from me), and wait for me to type `continue`.
6. **Ask, don't guess,** when: a data source is blocked or its terms forbid scraping, a financial method choice is unclear, money or legal text is involved, or a change would delete user data.
7. **Git hygiene.** Work on a branch per milestone (`m0-audit`, `m1-fixes`, ...). Small commits with clear messages. Never commit secrets.
8. **Windows dev machine.** Give commands that work in PowerShell, or run them through Docker.
9. **Use plan mode** before each milestone. Use subagents for independent work (e.g. tests and UI in parallel), but you own the final result.
10. **Keep a `CLAUDE.md`** at the repo root with these rules, the architecture, and how to run and test everything, so future sessions start with the right context.

# Milestone 2. Data foundation

- **Source registry** table: every source (exchange sites, company IR pages, Bank of Tanzania, Central Bank of Kenya, Bank of Uganda, national statistics offices, CMSA/CMA notices), with URL, what it provides, refresh frequency, terms-of-use notes, and last successful fetch.
- Check each source's terms of use. Where scraping isn't allowed or is fragile, write it down in KNOWN_GAPS and propose a licensed alternative (the exchange's own data service or a commercial African market data API). Ask me before signing up for anything paid.
- **Ingestion jobs** (Celery beat): daily prices and volumes, index levels, corporate actions (dividends, splits, rights issues), government bond yields, policy rates, inflation, FX rates. Each job stores the raw response, a hash and a timestamp. Retries with backoff. Alerts on failure.
- **Freshness**: every value carries an as-of date. The UI shows it. Data older than a set threshold is flagged as stale.
- **Document pipeline**: find, download and hash annual reports and interim results. Run the existing Docling + Camelot dual extraction. Disagreements become `EXTRACTION_CONFLICT` records shown in the UI and in the admin queue.
- **Validation**: balance sheet ties (assets = liabilities + equity), cash flow ties to cash movement, subtotals match line sums, same figure matches across years where restated. Failures block publication.
- Record zero-volume trading days (needed for beta).

Acceptance: jobs run on a schedule, a freshness dashboard exists in the admin area, NMB and CRDB have 5 years of reports ingested with validation results stored.

# Milestone 3. The flagship report: NMB Bank Plc (`/report/DSE:NMB`)

NMB comes first because it was analyzed in the CFA Institute Research Challenge, so results can be checked by hand.

Line-item analysis:
- Every major line: value, YoY change, CAGR, common-size share.
- Bank ratios: NIM, cost-to-income, cost of risk, NPL ratio, coverage, loan-to-deposit, ROE, ROA, CAR, dividend payout.
- A short rule-based note per line ("impairment charge rose X% while gross loans grew Y%"). The LLM may reword the note but may not change any number.

Beta (thin trading):
- Show side by side: raw daily OLS, weekly, monthly, Dimson (with lags), Scholes-Williams, and a bottom-up beta from regional listed bank peers, relevered for NMB.
- Show R-squared, standard error, observation count, share of zero-volume days.
- Pick the valuation beta with a documented rule and show why.

Cost of equity in TZS:
- Risk-free rate from the Bank of Tanzania long-dated Treasury bond yield (date and source shown).
- Mature market equity risk premium plus a Tanzania country risk premium from a named, dated source. Every input visible.

Valuation (bank template):
- Primary: residual income model and justified P/B from sustainable ROE, growth and cost of equity.
- Secondary: multi-stage dividend discount model.
- Cross-check: P/E and P/B against East African listed bank peers, each peer figure sourced.
- Bear, base and bull scenarios with explicit drivers (loan growth, NIM, cost of risk, cost-to-income, payout), probability-weighted into a 12-month target price.

Model view:
- Expected total return (price change + dividend yield) vs cost of equity, with bands set in `config/recommendation.yaml` and shown on the page.
- Output: fair value range, target price, confidence score (driven by data completeness, extraction conflicts, beta quality, data freshness).
- A feature flag `SHOW_TRADE_LABELS`. When off, show "Undervalued / Fairly valued / Overvalued". When on, show BUY / HOLD / SELL. Default off until I confirm the licensing position.

Non-financial and risks:
- Sections for macro and currency, regulation (Bank of Tanzania), credit concentration, governance and ownership, ESG. Each item cites a document. No unsourced statements.

Page layout:
- Header: name, last price, currency, last trade date, model view badge, target price, fair value range, confidence, data as-of date.
- Sections: Summary, Financial statements, Ratios, Beta, Valuation (ValuationExplainer shows the math step by step), Scenarios, Risks, Sources (EvidenceLineage).
- Every number clickable to its source.
- "Download PDF" in a research report layout (cover page, summary, valuation, scenarios, risks, sources, disclaimer).

Tests:
- Unit tests with hand-checked values for every ratio, every beta method, RI, DDM, scenario weighting and the model-view rule.
- Integration test: NMB balance sheet ties for every year, and at least 10 extracted figures match the PDF (list page numbers).

Acceptance: the NMB report loads with real data, every number traces to a source, tests pass, PDF export works, screenshots saved. List any figure you couldn't source.

# Milestone 4. Coverage and the analyst review loop

- Sector templates:
  - banks (as in M3),
  - insurers (P/B and ROE based, plus embedded-value style notes where data exists),
  - non-financial companies (FCFF DCF with WACC, plus EV/EBITDA and P/E cross-checks),
  - holding companies and funds (sum-of-parts or NAV).
  Each template picks its line items, ratios and models.
- Roll out to every listed DSE company, then the most traded NSE and USE companies. Companies with too little data get a clearly labeled "Limited coverage" page with what exists.
- **Report lifecycle**: `draft → in review → published → superseded`. Nothing reaches users until a human reviewer approves it.
- **Admin console** (role-protected): review queue, extraction conflicts, validation failures, source freshness, manual overrides (each override needs a reason and a source, and is logged), publish and unpublish.
- Auto-refresh: new results or a big price move put the report back into review. Users see "Update in progress" with the last published version.
- Report history: users can see past versions and how the model view changed.

Acceptance: all DSE companies have a published or "limited coverage" page, the review queue works end to end, overrides are audited.

# Milestone 5. Product experience

Results list real securities, weights, amounts, minimum trade size checks, currency exposure that matches the chosen markets, and the risk profile the user picked.
- **Portfolio tracker**: holdings, value in local and base currency, drift alerts, dividends received.
- **Learn section**: short guides (reading a bank's income statement, what beta means on a thin market, how we value companies). Link each from the matching part of the report.
- **Language**: English and Swahili with i18n from the start. Numbers and dates formatted per locale.
- **Mobile and low bandwidth**: mobile-first layouts, fast first load on slow 3G, charts that degrade to tables, images lazy-loaded.
- **Accessibility**: WCAG 2.1 AA (contrast, keyboard access, labels, focus states).
- Loading, empty and error states on every page.

Acceptance: Lighthouse mobile scores of 90+ for performance and accessibility on the landing and report pages, Playwright flows for sign-up, search, report, watchlist, wizard all pass in both languages.
